# 01 — 文法が優先順位を決める

`2 + 3 * 4` が `14` になるか `20` になるかは、文法の書き方で決まる。

## 1. ナイーブな書き方の問題

最初に「素朴に書いたらどうなるか」を見ておく。仮に bison でこう書いたとする。

```yacc
expr
    : INT_LIT
    | expr '+' expr
    | expr '-' expr
    | expr '*' expr
    | expr '/' expr
    ;
```

「式は整数か、式と式を演算子でつなげたもの」── 直感的だ。だが、これは**曖昧 (ambiguous)** だ。

入力 `2 + 3 * 4` に対して、bison は2通りの解釈ができてしまう。

```
解釈A:  expr             解釈B:  expr
        / | \                    / | \
     expr + expr             expr * expr
       2  / | \              / | \   4
        expr * expr        expr + expr
          3     4            2     3
```

解釈A なら `2 + 12 = 14`、解釈B なら `5 * 4 = 20`。bison は「どちらでも文法的に正しい」と判断し、競合 (shift/reduce conflict) を報告する。我々の意図（解釈A）は伝わらない。

解決方法は2つ:

1. bison の `%left` 宣言で優先順位と結合性を指定する（手軽だが文法の構造に表れない）。
2. **文法の階層そのもので優先順位を表現する**。

この章では (2) を選ぶ。文法を読めば優先順位がそのまま見える。BNF の伝統的な書き方だ。

## 2. 階層化された文法

優先順位の階層をそのまま文法の階層にする。

```yacc
expr     : add_expr ;

add_expr : mul_expr
         | add_expr '+' mul_expr
         | add_expr '-' mul_expr
         ;

mul_expr : unary
         | mul_expr '*' unary
         | mul_expr '/' unary
         | mul_expr '%' unary
         ;

unary    : primary
         | '-' unary
         ;

primary  : INT_LIT
         | '(' expr ')'
         ;
```

この5階層の文法が、優先順位の表を**そのまま** 表している。

| 階層 | 含まれる演算子 | 優先順位 |
|------|--------------|---------|
| `primary` | （リテラルと括弧） | （葉） |
| `unary` | `-` (単項) | 高い |
| `mul_expr` | `* / %` | 中 |
| `add_expr` | `+ -` | 低い |
| `expr` | （`add_expr` と同じ） | エントリポイント |

階層が深いほど、強く結びつく。

具体例で考えてみよう。`-2 + 3 * 4` という入力を、文法のどの階層がどの部分を受け持つかで分解する。

```
入力:   -2  +  3 * 4

  (-2) + 3 * 4         ← まず unary 階層が「-2」を塊として拾う
  unary + (3 * 4)      ← 次に mul_expr 階層が「3 * 4」を拾う（mul_expr(3) '*' unary(4) の形）
  add_expr + mul_expr  ← 最後に左の unary が add_expr まで持ち上がり、add_expr '+' mul_expr 規則に当てはまる
```

それぞれの階層が受け持つ部分が、入力のどこに対応するかを示している。`-2` の部分は単項マイナスなので `unary` 止まり、`3 * 4` の部分は乗算なので `mul_expr` 止まり、全体は加算なので `add_expr` まで上がる。

このように **「強い演算子（`*` など）は内側の階層で塊になり、弱い演算子（`+` など）は外側の階層で塊になる」** という棲み分けで優先順位が表現される。

## 3. 結合性も文法で決まる

`10 - 3 - 2` は、`(10 - 3) - 2 = 5` か、`10 - (3 - 2) = 9` か。C の規格では前者（左結合）。これも文法で表現できる。

`add_expr` の規則を見直そう。

```yacc
add_expr : mul_expr
         | add_expr '+' mul_expr
         | add_expr '-' mul_expr
         ;
```

二つ目と三つ目の規則。**左側が `add_expr`、右側が `mul_expr`** になっている。これが左結合の表現だ。

`10 - 3 - 2` を当てはめてみよう。

```
add_expr
├─ add_expr ← "10 - 3"
│  ├─ add_expr ← "10"
│  ├─ '-'
│  └─ mul_expr ← "3"
├─ '-'
└─ mul_expr ← "2"
```

「`add_expr` の左側にもう一段 `add_expr` がある」── これが左結合になる。再帰が左に伸びていく。

仮に右結合にしたければ、規則を裏返して `add_expr : mul_expr | mul_expr '+' add_expr` と書けばいい。すると右側に `add_expr` が伸び、`10 - (3 - 2)` になる。文法の書き方ひとつで結合性まで決まる。

C は加減と乗除は左結合なので、我々の文法もそうしている。

## 4. 単項マイナス

`unary` の階層を改めて見る。

```yacc
unary    : primary
         | '-' unary
         ;
```

「`unary` は、`primary` 単体か、または `-` の後にもう一段 `unary` を続けたもの」。これで `--5` のような連続にも対応する（実際に書く人はいないが、文法的には可能）。

`-(2 + 3)` のように、後ろに括弧つきの式が来る場合は、`unary → primary → '(' expr ')'` という経路で解釈される。`primary` が `'(' expr ')'` を受け入れるので、括弧の中身は再びフルの式に戻れる。これで括弧による優先順位の上書きも自然に表現できる。

## 5. 実際の AST の形

文法の階層は、AST の形に反映される。

| 入力 | AST |
|------|-----|
| `2 + 3 * 4` | <pre>BINARY +<br>├─ INT_LIT 2<br>└─ BINARY *<br>   ├─ INT_LIT 3<br>   └─ INT_LIT 4</pre> |
| `(2 + 3) * 4` | <pre>BINARY *<br>├─ BINARY +<br>│  ├─ INT_LIT 2<br>│  └─ INT_LIT 3<br>└─ INT_LIT 4</pre> |
| `-(2 + 3)` | <pre>UNARY -<br>└─ BINARY +<br>   ├─ INT_LIT 2<br>   └─ INT_LIT 3</pre> |

ポイントは2つ:

- **括弧は AST には残らない**。括弧は文法を曖昧でなくするための記号で、木が組み上がったら役目を終える。木の中で「先に計算するもの」は葉に近い場所にいる。
- `UNARY` は子を1つ、`BINARY` は左右2つの子を持つ。AST のノード型としては別物（`ast.h` で `NODE_UNARY` と `NODE_BINARY` を定義する）。

## 6. parser.y アクション部

文法規則の右側に `{ ... }` でアクションを書くと、bison がその規則で還元 (reduce) するときに実行される。アクションの中で AST を組み立てていく。

```yacc
add_expr
    : mul_expr                  { $$ = $1; }
    | add_expr '+' mul_expr     { $$ = new_binary('+', $1, $3); }
    | add_expr '-' mul_expr     { $$ = new_binary('-', $1, $3); }
    ;
```

- `$1`, `$2`, `$3` は規則の右辺の各シンボルが持つ値（`%type` で型を宣言したもの）。
- `$$` は規則の左辺（この規則で作られた塊）に持たせる値。
- `mul_expr` 単体の規則では「右辺の値をそのまま左辺に渡す」だけ (`$$ = $1`)。
- 演算子つきの規則では `new_binary` で AST ノードを作る。

`new_binary('+', $1, $3)` は ast.c で定義したコンストラクタ。第1引数が演算子の文字、第2引数が左の子、第3引数が右の子（`$2` は `'+'` 自身なので不要）。

`unary` の `'-' unary` 規則も同様で、`new_unary('-', $2)` を呼ぶ。

`primary` の `'(' expr ')'` 規則は `$$ = $2` だけでいい。「括弧の中身（`expr`、つまり `$2`）をそのまま外側に渡す」。これで括弧は AST 上に残らず消える。
