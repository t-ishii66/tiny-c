# 02 — System V AMD64 ABI

関数を呼ぶには **ルール** が要る。「引数はどこに置く？」「戻り値はどこから取る？」「呼び出し前後で壊してよいレジスタは？」── これを呼び出し側と呼び出される側で **取り決め** ておかないと、どこに何があるかわからなくなる。

この取り決めを **呼び出し規約 (calling convention)** または **ABI (Application Binary Interface)** と呼ぶ。x86-64 Linux で使われているのが **System V AMD64 ABI**。Mac (Apple Silicon の Rosetta x86-64 互換層) でも、Linux でも、これに従う。

## 1. ABI の核心 — レジスタ割り当て

### 整数引数

最初の **6 個** の整数（または整数互換の値、ポインタも含む）の引数は、次のレジスタに順番に置かれる:

| 引数番号 | 64ビット | 32ビット |
|---------|---------|---------|
| 1 | `%rdi` | `%edi` |
| 2 | `%rsi` | `%esi` |
| 3 | `%rdx` | `%edx` |
| 4 | `%rcx` | `%ecx` |
| 5 | `%r8`  | `%r8d` |
| 6 | `%r9`  | `%r9d` |

7 個目以降はスタックに積む。tiny-c では **最大 6 個** に限定（CLAUDE.md 参照）するので、スタック渡しは扱わない。

`add(3, 4)` を呼ぶ側はこうする:

```
movl $3, %edi           # arg 1 = 3
movl $4, %esi           # arg 2 = 4
call add
```

呼ばれた側は `%edi` と `%esi` を読めば引数が手に入る。

### 戻り値

整数の戻り値は **`%rax`** に入れる（32ビットなら下位 `%eax`）。

我々の codegen の約束事「式の値は `%eax`」は、**この ABI と一致するように**設計されていた。`return expr;` で `gen_expr(expr)` の後に `leave; ret` するだけで、自然に正しい場所に値が乗る。

## 2. caller-saved と callee-saved

レジスタは「呼び出し側 (caller)」と「呼び出される側 (callee)」のどちらが保存責任を持つかで2種類に分かれる。

### caller-saved (volatile, 呼び出し側保存)
呼ばれる側は **自由に上書きしてよい** レジスタ。呼び出し側は、call の前に「失われたら困る値」を自分で退避する必要がある。

- `%rax`、`%rcx`、`%rdx`、`%rsi`、`%rdi`、`%r8`、`%r9`、`%r10`、`%r11`

引数を渡すレジスタ（`%rdi`〜`%r9`）が全部 caller-saved なのは納得できる ── 引数は使い捨てだから、callee はこれらを潰しても問題ない。

### callee-saved (non-volatile, 呼び出される側保存)
呼ばれる側は、これらを使うなら **保存して戻すまで** 同じ値に戻す責任がある。

- `%rbx`、`%rbp`、`%rsp`、`%r12`、`%r13`、`%r14`、`%r15`

`%rbp` が callee-saved なのは重要。だから関数のプロローグの **第一行** が `pushq %rbp` だ ── 呼び出し元の `%rbp` を必ず退避し、`leave` で戻す。これがなかったら、呼び出し元のローカル変数アクセスが全部壊れる。

`%rsp` も callee-saved（ただし通常の意味で「保存して戻す」というより、自然に戻る）。プロローグで `subq` した分は、エピローグの `leave` (= `movq %rbp, %rsp; popq %rbp`) で復元される。

### tiny-c は何を使うか

- 引数渡し: `%rdi`〜`%r9` を使う（caller-saved、規約通り）。
- 戻り値: `%rax`（caller-saved、規約通り）。
- 一時値: `%rax`、`%rcx` のみ（両方 caller-saved）。
- フレームポインタ: `%rbp`（callee-saved、プロローグで退避）。

callee-saved レジスタ (`%rbx`、`%r12`〜`%r15`) は **使わない**。使えばコード生成は最適化できる（スタック push/pop が減る）が、callee-saved は退避が必要になり、複雑になる。tiny-c は教育用なので、シンプルさを優先。

## 3. スタックの 16 バイト整列

これが ABI で最も注意を要するルール。

> **`call` 命令の直前で、`%rsp` は 16 バイト境界に整列されていなければならない**。

なぜ整列が必要か? 関数のプロローグ後 (`pushq %rbp` してから `subq` する前) に **`%rsp` が 16 の倍数** になることを、callee は前提にしている。SSE 命令などで「16バイトアラインのメモリアクセス」を使うとき、これを前提にしないとセグフォを起こす。

`call` 命令は **戻り番地 (8バイト)** をスタックに積むので:

- `call` の直前: `%rsp` は 16 の倍数 (16N)。
- `call` 後（callee 入った直後）: `%rsp` は 16N - 8 (= 8 mod 16)。
- callee の `pushq %rbp` 後: `%rsp` は 16N - 16 = 16(N-1) (= 0 mod 16)。

callee はこの「`pushq %rbp` 後に 16-aligned」を前提にして、ローカル領域を `subq` で確保する。**16 の倍数だけ subq する**ことで、その後も 16-aligned に保てる。

整理すると:

```
caller の責任: call の前に %rsp を 16-aligned に整える
callee の最初: pushq %rbp で 16-aligned に戻る
callee の subq: 16 の倍数だけ subq する → ローカル領域中も 16-aligned
```

これを守らない限り、関数呼び出しは（一見動いて見えても）どこかで壊れる。

## 4. プロローグとエピローグ、改めて

ch01 から書いてきたプロローグ・エピローグの正体は、ABI の要請をそのまま実装したものだ。

```
プロローグ:
  pushq %rbp           # callee-saved %rbp を退避
  movq %rsp, %rbp      # 新しいフレームベース
  subq $N, %rsp        # ローカル領域確保 (N は 16 の倍数)

エピローグ:
  leave                # = movq %rbp, %rsp; popq %rbp
  ret                  # スタック先頭の戻り番地に飛ぶ
```

`pushq %rbp` は ABI 規定（callee-saved の保存）。`subq` の量は ABI 制約（16 の倍数）。`leave; ret` は対応する逆操作。**ABI の言葉で書かれている**のだ。

ch04 までの tiny-c は、変数のたびに `subq $8, %rsp` と1個ずつ伸ばしていた。8 ずつだから 16-aligned が崩れる。ch04 まではそれでも動いていた ── **call をしないから**。call さえしなければ、整列が崩れていてもセグフォにはならない。

ch05 で関数呼び出しが入ると、**急に 16-aligned が必須** になる。ch04 までの lazy 方式は通用しない。次のサブ章 (`03_frame.md`) で、フレームの作り方を再設計する。

## 5. 可変引数関数 (variadic) と `%al`

`printf("%d %d", a, b)` のような可変引数関数を呼ぶとき、ABI は追加の規則を課している:

> 可変引数を含む関数を呼ぶときは、`%al` (= `%rax` の下位8ビット) に「**XMM レジスタを使った浮動小数点引数の数**」を入れること。

`printf` のような関数は、`...` の中に何個 float/double があるかを ABI レベルでは知る術がないので、`%al` で hint を渡す。整数しか渡さなければ `%al = 0`。

tiny-c は浮動小数点を扱わないので、**常に `movl $0, %eax`** を `call` の直前に出す。これで `%al = 0` になる。可変引数でない関数にとっても、`%al = 0` は無害（書き換えるレジスタは戻り値で使われるが、`call` 後に上書きされるのでどうせ捨てる）。

```
movl $0, %eax        # %al = 0  (XMM regs used = 0)
call printf
```

これで `printf` が安全に呼べる（ch06 で文字列リテラルが使えるようになって実際に exercise する）。tiny-c の通常の関数呼び出しでも常にこの 1 行を出す ── 可変引数かどうかの判別が要らないので、コードがシンプルになる。

## 6. 関数呼び出しの全体像

「ABI に従う」を実装に落とすと、こういう手順になる。

```
[呼び出し側 (caller)]
  1. 引数を %rdi, %rsi, %rdx, %rcx, %r8, %r9 に積む
  2. %rsp が 16-aligned であることを確認（ずれていればパディング）
  3. movl $0, %eax  (variadic ABI の保険)
  4. call name
  5. 戻り値は %rax にある

[呼ばれる側 (callee)]
  1. pushq %rbp; movq %rsp, %rbp  (フレーム確立)
  2. subq $N, %rsp  (N = 16 の倍数)
  3. %edi, %esi, ... を、対応するスタックスロットにコピー (引数の spill)
  4. 関数本体を実行
  5. 戻り値を %eax に入れる
  6. leave; ret
```

これがすべて。次の2章でそれぞれを実装に落とす。

## 7. まとめ

- 整数引数の最初の6個は `%rdi, %rsi, %rdx, %rcx, %r8, %r9` の順に積む。
- 戻り値は `%rax` (32ビットなら `%eax`)。
- `%rbp` は callee-saved。プロローグで pushq、エピローグで restore。
- **`call` の直前で `%rsp` は 16-aligned** ── これが ABI 最大の制約。
- 可変引数 ABI のため、`call` の直前に `movl $0, %eax`。
