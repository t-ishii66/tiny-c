# 第7章 — 最適化とバックパッチ

## 0. はじめに

ch01 から ch06 まで、生成されるアセンブリは「**素直で愚直**」だった。`return 2 + 3 * 4;` をコンパイルすると 11 行の asm が出た ── レジスタは `%eax` しか使わず、`pushq` と `popq` で中間値を退避し、AT&T 流の3命令で計算する。読みやすいが、**明らかに無駄が多い**。

加えて ch06 までの codegen は **二相構成**（collect_locals → gen_stmt）だった。プロローグの `subq $N, %rsp` で N（フレームサイズ）が決まっていないと書けないので、先に AST を 1 回歩いて N を確定してから本体を出力する、という手順だ。

第 7 章では、これら 2 つの「課題」をまとめて解決する。鍵になるのは **アセンブリ出力をメモリバッファに溜める** こと。これだけで:

| テーマ | 内容 | バッファとの関係 |
|------|------|----------------|
| **AST 最適化**（節 01）| 定数畳み込み + 代数的単純化 | 直接は使わない（AST 上で完結） |
| **バックパッチ**（節 02、必須）| プロローグの `subq $N` を後埋め → codegen が単一パスに | バッファ上で `ftell` / `fseek` |
| **ピープホール最適化**（節 03）| 生成 asm を眺めて隣接命令を書き換える | バッファの内容を読んで再出力 |

バックパッチと最適化は **別物**。バックパッチは codegen の構造を単純化するための仕掛けで、出力されるコードの内容は変わらない。最適化は実際にコードを短くする。`--no-opt` で外せるのは AST 最適化とピープホールだけで、**バックパッチは常に有効**。

ch01〜ch06 で「コンパイラの中身（lexer → parser → AST → codegen）」を一通り作ったが、ch07 では:

```
ソース → 字句解析 → 構文解析 → AST → [AST 最適化] → codegen → asm → [ピープホール] → 出力 asm
                                  ↑                  ↑                  ↑
                                  ch07 で追加        単一パス化         ch07 で追加
                                                     (バックパッチ)
```

asm はメモリバッファに書かれ、ピープホールで整形されてから stdout に流れる。バックパッチも同じバッファ上で行う。

## 1. 効果のサンプル

`return 2 + 3 * 4;` のコンパイル結果:

**最適化なし** (11 行)

```asm
main:
  pushq %rbp
  movq %rsp, %rbp
  movl $4, %eax
  pushq %rax
  movl $3, %eax
  popq %rcx
  imull %ecx, %eax
  pushq %rax
  movl $2, %eax
  popq %rcx
  addl %ecx, %eax
  leave
  ret
```

**最適化あり** (5 行)

```asm
main:
  pushq %rbp
  movq %rsp, %rbp
  movl $14, %eax
  leave
  ret
```

`2 + 3 * 4` が **コンパイル時に 14 に畳まれ**、しかも末尾の暗黙 `return` の dead code も除去された結果。CPU が走る命令数が劇的に減った。

`printf("hello\n")` も:

**最適化なし**: `pushq %rax; popq %rdi` が残る。
**最適化あり**: `movq %rax, %rdi` 1 命令に置き換わり、末尾の dead code も消える。

## 2. ch06 との差分

| ファイル | 変更 |
|---------|------|
| `lexer.l` / `parser.y` / `ast.c` | **変更なし** |
| `ast.h` | `Node->lvar` フィールドを **削除**（バックパッチで Phase 1 が消えたので不要）|
| `codegen.c` | **二相 → 単一パス**（`collect_locals` 削除）、プロローグを `ftell`/`fseek` でバックパッチ |
| `optimize.h` / `optimize.c` | **新規** ── `optimize_ast` と `peephole` の2関数 |
| `main.c` | 常に `open_memstream` を使う、`--no-opt` 対応、ピープホールを通す |
| `Makefile` | `optimize.c` をビルド対象に追加 |

最適化（AST + ピープホール）は **完全に別パス** として codegen の前後に挟まる。バックパッチは codegen の **内部構造の改善** で、外から見れば二相が一相になっただけ ── 出力されるコードは ch06 と同じ。両者は「コンパイラの構造を進化させる」ch07 の 2 本柱。

## 3. 使い方

```bash
$ ./tinyc test.c              # 最適化あり（デフォルト）
$ ./tinyc --no-opt test.c     # 最適化なし（比較用）
$ ./tinyc --dump-ast test.c   # 最適化後の AST を表示
$ ./tinyc --no-opt --dump-ast test.c  # 最適化前の AST を表示
```

`--no-opt` オプションがあるので、ビフォー・アフターを直接見比べられる。ch07 の docs ではこの形でデモを示す。
