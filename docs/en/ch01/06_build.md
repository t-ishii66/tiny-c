# 06 — main.c, Makefile, and assembling the whole thing

We have `lexer.l`, `parser.y`, `ast.h/ast.c`, and `codegen.c/codegen.h`. What remains is the **entry point** (`main.c`) that ties them together, and the build recipe (`Makefile`).


## 1. Who does what

```
+---------+                                                +---------+
| .c in   |                                                | .s out  |
+----+----+                                                +----+----+
     |                                                          ^
     v                                                          |
+----------+   +-----------+   +-------+   +-----------+   +----+----+
|  lexer   |─→ |  parser   |─→ |  AST  |─→ | codegen   |─→ |   FILE  |
| (flex)   |   | (bison)   |   |       |   |           |   |  (stdout)|
+----------+   +-----------+   +-------+   +-----------+   +---------+
                  ^                            ^
                  |                            |
            +-----+----+                +------+-----+
            | main.c   |                | main.c     |
            | yyparse  |                | codegen()  |
            +----------+                +------------+
```

`main.c` reads the arguments, opens the file, calls `yyparse()`, and hands the resulting AST to `codegen()` — its job is just **outer plumbing**.


## 2. Reading main.c

```c
#include <stdio.h>
#include <string.h>
#include "ast.h"
#include "codegen.h"

extern int yyparse(void);
extern FILE *yyin;
extern Node *program;

int main(int argc, char **argv) {
    if (argc < 2) {
        fprintf(stderr, "usage: tinyc [--dump-ast] <file>\n");
        return 1;
    }

    int dump_ast = 0;
    char *filename = argv[1];

    if (strcmp(argv[1], "--dump-ast") == 0) {
        dump_ast = 1;
        if (argc < 3) { fprintf(stderr, "usage: tinyc --dump-ast <file>\n"); return 1; }
        filename = argv[2];
    }

    yyin = fopen(filename, "r");
    if (!yyin) { perror(filename); return 1; }

    yyparse();
    fclose(yyin);

    if (dump_ast) {
        print_ast(program, 0);
    } else {
        codegen(program, stdout);
    }
    return 0;
}
```

Going through it:

### `extern` declarations

```c
extern int yyparse(void);
extern FILE *yyin;
extern Node *program;
```

These declarations say "these are defined in other files."

- `yyparse()` is defined in `parser.tab.c` (generated by bison). Calling it kicks off parsing.
- `yyin` is a global variable defined in `lex.yy.c` (generated by flex). It's a `FILE *` that flex reads input from.
- `program` is a global variable **we** defined in `parser.y`. After parsing finishes, it holds the root of the AST.

`extern` says "pull these in from another object file at link time." It doesn't define anything.

### Argument handling

```c
if (argc < 2) {
    fprintf(stderr, "usage: tinyc [--dump-ast] <file>\n");
    return 1;
}

int dump_ast = 0;
char *filename = argv[1];

if (strcmp(argv[1], "--dump-ast") == 0) {
    dump_ast = 1;
    if (argc < 3) { fprintf(stderr, "usage: tinyc --dump-ast <file>\n"); return 1; }
    filename = argv[2];
}
```

We accept two forms: `./tinyc file.c` or `./tinyc --dump-ast file.c`. At least one argument (the filename) is required. If `--dump-ast` is given, we set a flag and pick up the filename from the second argument.

### Opening the input file

```c
yyin = fopen(filename, "r");
if (!yyin) { perror(filename); return 1; }
```

Assign the open `FILE *` to `yyin`. That alone makes flex read from this file.

### Running the parse

```c
yyparse();
fclose(yyin);
```

When `yyparse()` runs, here's what happens inside:

1. bison's loop begins.
2. flex's `yylex()` is called to pull one token.
3. Grammar rules are tried; on a match, the action runs (constructing nodes via `new_xxx`).
4. Repeat until EOF.
5. By the end, the global `program` holds the assembled AST.

`yyparse()` returns 0 on success, nonzero on failure. For now, on a syntax error `yyerror` calls `exit(1)`, so we don't check the return value.

### Using the result

```c
if (dump_ast) {
    print_ast(program, 0);
} else {
    codegen(program, stdout);
}
return 0;
```

If `--dump-ast` is set, print the AST. Otherwise, emit assembly to `stdout`. Because the assembly goes to `stdout`, the user redirects with `./tinyc file.c > file.s`.


## 3. main.c is essentially unchanged from here on

`main.c` **doesn't substantively change through Chapter 6**. All it does is the outer choreography: "handle arguments → call `yyparse` → output the AST."

The flesh grows in `lexer.l` (new tokens), `parser.y` (new grammar rules), `ast.h/ast.c` (new node kinds), and `codegen.c` (new code-generation patterns). **These four files are where the compiler expands.**


## 4. Reading the Makefile

> The Makefile walkthrough that follows is fine to skim. If you're not interested, jump to "6. Build & run." Writing Makefiles from scratch isn't a common task day-to-day anymore. We use a Makefile here because it's a great teaching tool for expressing dependencies concisely. Just enough understanding of "this is how the build is wired up" is plenty to move on.

A `Makefile` is the build recipe read by the `make` command. You declare what depends on what.

```makefile
CC      = gcc
CFLAGS  = -Wall -g -Isrc -Ibuild
BUILD   = build

SRCS    = src/ast.c src/codegen.c src/main.c
OBJS    = $(BUILD)/ast.o $(BUILD)/codegen.o $(BUILD)/main.o \
          $(BUILD)/parser.tab.o $(BUILD)/lex.yy.o

tinyc: $(OBJS)
	$(CC) -o $@ $^

$(BUILD)/parser.tab.c $(BUILD)/parser.tab.h: src/parser.y | $(BUILD)
	bison -d -o $(BUILD)/parser.tab.c $<

$(BUILD)/lex.yy.c: src/lexer.l $(BUILD)/parser.tab.h | $(BUILD)
	flex -o $@ $<

$(BUILD)/lex.yy.o: $(BUILD)/lex.yy.c
	$(CC) $(CFLAGS) -Wno-unused-function -c -o $@ $<

$(BUILD)/parser.tab.o: $(BUILD)/parser.tab.c
	$(CC) $(CFLAGS) -c -o $@ $<

$(BUILD)/%.o: src/%.c | $(BUILD)
	$(CC) $(CFLAGS) -c -o $@ $<

$(BUILD):
	mkdir -p $(BUILD)

clean:
	rm -rf $(BUILD) tinyc

.PHONY: clean
```

The Makefile syntax is its own thing, but the idea is simple. Each rule:

```
target: prerequisites
	command
```

"To build the target, these prerequisites are needed; once they're in place, run this command." Command lines must start with a **tab character** (not spaces — a classic trap).

### Variable definitions

```makefile
CC      = gcc
CFLAGS  = -Wall -g -Isrc -Ibuild
BUILD   = build

SRCS    = src/ast.c src/codegen.c src/main.c
OBJS    = $(BUILD)/ast.o $(BUILD)/codegen.o $(BUILD)/main.o \
          $(BUILD)/parser.tab.o $(BUILD)/lex.yy.o
```

- `CC` is the compiler.
- `CFLAGS` are the compile options: `-Wall` enables all warnings; `-g` includes debug info; `-Isrc -Ibuild` adds `src/` and `build/` to the header search path.
- `BUILD` is where build artifacts live: the `build/` directory.
- `SRCS` lists the hand-written C sources; `OBJS` lists the object files for the final link.
- `\` continues a line.

### Linking tinyc

```makefile
tinyc: $(OBJS)
	$(CC) -o $@ $^
```

"To build `tinyc`, all of `$(OBJS)` are needed." The command is "`gcc -o tinyc <all .o files>`."

`$@` is the target name (here `tinyc`); `$^` is all prerequisites (here all of `$(OBJS)`). These are make's automatic variables.

### Generating the parser with bison

```makefile
$(BUILD)/parser.tab.c $(BUILD)/parser.tab.h: src/parser.y | $(BUILD)
	bison -d -o $(BUILD)/parser.tab.c $<
```

To produce `build/parser.tab.c` and `build/parser.tab.h`, we need `src/parser.y`. The command runs bison with `-d` (also produce the header) and `-o` (output path).

The `$(BUILD)` after the `|` is an **order-only prerequisite**. It says "make the `build/` directory if it doesn't exist, but don't use its mtime when deciding whether to rebuild." Without this, every time `build/`'s mtime changed, bison would re-run unnecessarily.

`$<` is the automatic variable for "the first prerequisite" (here `src/parser.y`).

### Generating the lexer with flex

```makefile
$(BUILD)/lex.yy.c: src/lexer.l $(BUILD)/parser.tab.h | $(BUILD)
	flex -o $@ $<
```

To produce `build/lex.yy.c`, we need `src/lexer.l` and `build/parser.tab.h`. **The header is required** because `lexer.l` does `#include "parser.tab.h"`. bison must run first and produce the header before flex's output can compile.

When the dependencies are written correctly, `make` enforces the order automatically.

### Per-file compile rules

```makefile
$(BUILD)/lex.yy.o: $(BUILD)/lex.yy.c
	$(CC) $(CFLAGS) -Wno-unused-function -c -o $@ $<

$(BUILD)/parser.tab.o: $(BUILD)/parser.tab.c
	$(CC) $(CFLAGS) -c -o $@ $<

$(BUILD)/%.o: src/%.c | $(BUILD)
	$(CC) $(CFLAGS) -c -o $@ $<
```

Three compile rules:

- `lex.yy.o` adds `-Wno-unused-function`. flex emits some unused helper functions, and we suppress that warning.
- `parser.tab.o` compiles plainly.
- `%` is a wildcard. The pattern rule says "build `build/foo.o` from `src/foo.c`." That covers `ast.o`, `codegen.o`, and `main.o`.

### Making the directory; cleaning

```makefile
$(BUILD):
	mkdir -p $(BUILD)

clean:
	rm -rf $(BUILD) tinyc

.PHONY: clean
```

- Rule to create the `build/` directory.
- The `clean` target wipes all build artifacts.
- `.PHONY: clean` says "even if a file named `clean` exists, ignore it and always run the command."


## 5. The build dependency graph

```
src/parser.y ─→ build/parser.tab.c ─→ build/parser.tab.o ──┐
            └─→ build/parser.tab.h ─┐                        │
                                    │                        │
src/lexer.l ────────────────────────┴→ build/lex.yy.c ─→ build/lex.yy.o ──┤
                                                                          │
src/ast.c    ─────────────────────────────────────→ build/ast.o ─────────┤
                                                                          │
src/codegen.c ────────────────────────────────────→ build/codegen.o ─────┤
                                                                          │
src/main.c   ─────────────────────────────────────→ build/main.o ────────┤
                                                                          ↓
                                                                       tinyc
```

`make` reads this graph and runs commands in the necessary order. Anything unchanged is skipped.


## 6. Build & run

If you're reading along and want to run the commands yourself, clone the repository first. Each chapter's complete source lives under `steps/chNN/`, and the top-level `Makefile` builds the final ch07 form.

```bash
$ git clone https://github.com/t-ishii66/tiny-c.git
$ cd tiny-c
$ cd steps/ch01     # this chapter's source
```

Prerequisites: `gcc`, `flex`, `bison`, `make`. Subsequent chapters reuse this clone — they just `cd` into a different `steps/chNN`.

With all the files in place, we can build.

```bash
$ make
mkdir -p build
gcc -Wall -g -Isrc -Ibuild -c -o build/ast.o src/ast.c
gcc -Wall -g -Isrc -Ibuild -c -o build/codegen.o src/codegen.c
gcc -Wall -g -Isrc -Ibuild -c -o build/main.o src/main.c
bison -d -o build/parser.tab.c src/parser.y
gcc -Wall -g -Isrc -Ibuild -c -o build/parser.tab.o build/parser.tab.c
flex -o build/lex.yy.c src/lexer.l
gcc -Wall -g -Isrc -Ibuild -Wno-unused-function -c -o build/lex.yy.o build/lex.yy.c
gcc -o tinyc build/ast.o build/codegen.o build/main.o build/parser.tab.o build/lex.yy.o
```

`tinyc` is built. Let's run it.

```bash
$ echo 'int main() { return 42; }' > test.c

$ ./tinyc --dump-ast test.c
FUNC_DEF main
  BLOCK
    RETURN
      INT_LIT 42

$ ./tinyc test.c
  .text
  .globl main
main:
  pushq %rbp
  movq %rsp, %rbp
  movl $42, %eax
  leave
  ret

$ ./tinyc test.c > test.s
$ gcc -o test test.s
$ ./test
$ echo $?
42
```

**It works.** The compiler produced an executable.

(Note: running the executable requires x86-64 Linux. On Mac or Windows the compiler itself works, but assembling and running its output requires a different environment.)


## 7. Recap

What our Chapter 1 compiler **can do**:

- Parse a function definition `int main() { ... }`
- Handle the `return` statement
- Put an integer literal in `%eax` and return from the function
- Print the AST with `--dump-ast`

What it **can't** do: arithmetic, variables, `if`/`while`, parameters or multiple functions, strings, arrays, pointers, calling external functions — those come in Chapters 2 onward.

The file list:

| File | Role |
|---------|------|
| `ast.h` | Node type definitions |
| `ast.c` | Node constructors and debug output |
| `lexer.l` | Splits the string into tokens |
| `parser.y` | Builds the AST from tokens |
| `codegen.h` | Code generation interface |
| `codegen.c` | Emits assembly from the AST |
| `main.c` | Ties it all together |
| `Makefile` | Build recipe |

From Chapter 2 onward, we'll add flesh to this skeleton by extending lexer / parser / AST / codegen.
