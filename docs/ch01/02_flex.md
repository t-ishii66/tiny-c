# 02 — flex 入門 と lexer.l

字句解析器（**lexer**）は、ソースコードの文字列を**トークン**の列に変換するプログラムだ。

```
"int main() { return 42; }"
              ↓ 字句解析器
INT  IDENT(main)  '('  ')'  '{'  RETURN  INT_LIT(42)  ';'  '}'
```

これを手書きすると退屈で間違えやすい。そこで使うのが **flex** ── **字句解析器を自動生成するプログラム**だ。正規表現とアクション（マッチしたときにやること）を書いた定義ファイルから、C のソースコードを生成してくれる。

```
lexer.l   ─ flex ─→   lex.yy.c   （これが字句解析器の C コード）
```

`lexer.l` を書き、flex に通して `lex.yy.c` を生成し、それを gcc でコンパイルすれば字句解析器の出来上がり。


## 1. flex ファイルの構造

`.l` ファイル（flex の定義ファイル）は、3つの区画に分かれている。`%%` という行で区切る。

```flex
%{
   /* C コード（先頭）*/                     ← 第1区画
%}

   /* オプション */

%%

   /* パターンとアクションの定義 */          ← 第2区画

%%

   /* C コード（末尾）*/                     ← 第3区画
```

| 区画 | 内容 |
|------|------|
| 第1区画 | C のヘッダ #include やオプション宣言。`%{ ... %}` で囲んだ部分は生成コードの先頭にそのまま貼られる |
| 第2区画 | パターン → アクション。**ここが本体** |
| 第3区画 | C の補助関数（今回は使わない） |

`%%` は「区画の境界線」だと思えばよい。


## 2. パターンとアクション

第2区画はこういう書き方をする。

```flex
パターン     { アクション }
パターン     { アクション }
...
```

flex は、入力された文字列を読みながら、「どのパターンにマッチするか」を判定する。マッチしたら、対応するアクション（C のコード）を実行する。

例：

```flex
"hello"      { printf("hello!\n"); }
"world"      { printf("world!\n"); }
[0-9]+       { printf("number: %s\n", yytext); }
.            { /* 何もしない */ }
```

ここで `yytext` は flex が用意してくれる変数で、**マッチした文字列そのもの**が入っている。`[0-9]+` が `42` にマッチしたら、`yytext` は `"42"` という文字列になる。


## 3. 二つの大事なルール

flex がパターンを選ぶときには、二つの暗黙のルールがある。

### ルール A：最長一致

複数のパターンが同じ場所からマッチするとき、**最も長くマッチする**ものが選ばれる。

例えば次のパターンがあったとする。

```flex
"if"          { return IF; }
[a-zA-Z_]+    { return IDENT; }
```

入力が `if` だけなら、両方のパターンが「`if` の2文字」にマッチして同点。

ところが入力が `iframe` の場合、`"if"` は2文字しかマッチしないが、`[a-zA-Z_]+` は6文字すべてにマッチする。flex は最長一致を取り、`iframe` を IDENT として扱う。これが「最長一致の原則」だ。

### ルール B：先勝ち

最長一致が同じ長さで複数あるときは、**先に書いたパターン**が勝つ。

```flex
"int"                    { return INT; }
[a-zA-Z_][a-zA-Z0-9_]*   { return IDENT; }
```

入力が `int` のとき、両方とも「`int` の3文字」にマッチして同点。順序が先の `"int"` のほうが採用される。だから `int` は IDENT ではなく INT トークンになる。

**順序が逆だと、`int` が IDENT として認識されてしまい、キーワードと識別子が区別できなくなる。** だからキーワードは識別子より先に書く。


## 4. yylval — 値を持ち帰る

`return INT;` のように書くと、flex はトークン名（INT）だけを呼び出し元に返す。でも整数リテラルや識別子の場合は、**値そのもの**も渡したい。`42` を読み取ったら「INT_LIT トークン、値は 42」と伝えたい。

そのための仕組みが `yylval` だ。`yylval` は flex と bison が共有する変数で、トークンに付随する値を入れておく場所。

```flex
[0-9]+    { yylval.int_val = atoi(yytext); return INT_LIT; }
```

これは「数字列にマッチしたら、`yytext`（マッチした文字列、たとえば `"42"`）を `atoi` で整数に変換して `yylval.int_val` に入れ、INT_LIT トークンを返す」という意味だ。

`yylval` は構造体（共用体）で、いろんな種類の値を入れられる。整数なら `int_val`、文字列なら `name`、というふうにフィールドを使い分ける。この共用体の定義は次の節（bison）で書く。


## 5. ch01 の lexer.l 全体

```flex
%{
#include "ast.h"
#include "parser.tab.h"
%}

%option noyywrap

%%
"int"       { return INT; }
"return"    { return RETURN; }
[0-9]+      { yylval.int_val = atoi(yytext); return INT_LIT; }
[a-zA-Z_][a-zA-Z0-9_]*  { yylval.name = strdup(yytext); return IDENT; }
"("         { return '('; }
")"         { return ')'; }
"{"         { return '{'; }
"}"         { return '}'; }
";"         { return ';'; }
[ \t\n]+    { /* skip whitespace */ }
"//".*      { /* skip line comments */ }
.           { fprintf(stderr, "unknown char: %c\n", *yytext); exit(1); }
%%
```

19行。これだけで字句解析器が手に入る。


## 6. 1行ずつ読む

### 第1区画（先頭）

```flex
%{
#include "ast.h"
#include "parser.tab.h"
%}
```

`%{ ... %}` で囲んだ部分は、生成される C コードの先頭にそのままコピーされる。

- `ast.h` は AST のノード型を使うため（`yylval` の中で `Node *` を使う場面が将来出てくる）。
- `parser.tab.h` は bison が生成するヘッダファイルで、トークン名（INT, RETURN, INT_LIT, ...）の定義と `yylval` の型定義が入っている。これがないとトークン名が未定義になる。

### オプション

```flex
%option noyywrap
```

flex はデフォルトで「ファイルを読み終えたら次のファイルがあるかチェックする」`yywrap` という関数を呼ぼうとする。複数ファイルを連続して処理するためのものだが、今回は1ファイルしか扱わないので不要。`noyywrap` で無効化する。これを書かないとリンク時に `yywrap` の実装を要求される。

### 第2区画（パターンとアクション）

```flex
"int"       { return INT; }
"return"    { return RETURN; }
```

キーワード。`int` という文字列が来たら INT トークン、`return` なら RETURN トークン。値は持たないので `yylval` は触らない。**識別子のパターンより先に書く**ことが重要。

```flex
[0-9]+      { yylval.int_val = atoi(yytext); return INT_LIT; }
```

整数リテラル。数字の連続にマッチしたら、`yytext`（マッチした文字列）を `atoi` で int に変換して `yylval.int_val` に入れ、INT_LIT トークンを返す。

```flex
[a-zA-Z_][a-zA-Z0-9_]*  { yylval.name = strdup(yytext); return IDENT; }
```

識別子。「アルファベット/アンダースコアで始まり、続きはアルファベット/数字/アンダースコア」。`yytext` は flex の内部バッファを指すポインタで、次のマッチで上書きされる。だから `strdup` でヒープにコピーしてから `yylval.name` に入れる。

```flex
"("         { return '('; }
")"         { return ')'; }
"{"         { return '{'; }
"}"         { return '}'; }
";"         { return ';'; }
```

記号。値を持たない。`return '('` のように、トークン名を**文字そのもの**にしている。これは bison の流儀で、1文字の記号はトークン番号としてその文字コードを使う。トークンを別名で定義する手間が省ける。

> **補足: トークン番号はぶつからないのか？**
>
> `yylex()` が返す値はすべて `int` 一本だ。`return '('` は 40（ '(' の ASCII コード ）を返し、`return IDENT` は別の整数を返す。両者がぶつかると困る。
>
> bison は名前付きトークン（`INT`, `RETURN`, `INT_LIT`, `IDENT` ...）に **256 以降の整数**を順に割り当てる。だから ASCII の範囲（0〜255）にいる1文字トークンとは絶対にぶつからない。次の章（03_bison.md）でできる `parser.tab.h` を覗くと、こんな定義が並んでいる:
>
> ```c
> #define INT       258
> #define RETURN    259
> #define INT_LIT   260
> #define IDENT     261
> ```
>
> 整理するとこうなる:
>
> | 戻り値の範囲 | 意味 |
> |-----------|-----|
> | 0 | EOF |
> | 1〜255 | 1文字トークン（その文字の ASCII コード）|
> | 256〜 | 名前付きトークン（bison が割り振る）|
>
> パーサ側は受け取った `int` がどの範囲にあるかで区別する。我々はこの番号を意識する必要はなく、`'('` や `IDENT` という名前で書けばよい。

```flex
[ \t\n]+    { /* skip whitespace */ }
"//".*      { /* skip line comments */ }
```

空白とコメント。マッチしてもアクションで何もしない（`return` しない）と、flex はそのトークンを呼び出し元に渡さず、次のマッチを試す。つまり**読み飛ばし**になる。

```flex
.           { fprintf(stderr, "unknown char: %c\n", *yytext); exit(1); }
```

最後のフォールバック。どのパターンにもマッチしなかった1文字は、ここでエラーになる。`.` は「改行以外の任意の1文字」だが、改行は上の `[ \t\n]+` で先にマッチするから問題ない。


## 7. 実際のトークン化を追ってみる

入力 `int main() { return 42; }` を、この lexer がどう処理するか追ってみよう。flex は左から順に、最長一致＋先勝ちでマッチしていく。

| 位置 | 入力の残り | マッチ | 動作 |
|-----|-----------|-------|------|
| 0 | `int main() { return 42; }` | `"int"` | INT を返す |
| 3 | ` main() { return 42; }` | `[ \t\n]+` (` `) | 読み飛ばし |
| 4 | `main() { return 42; }` | `[a-zA-Z_]...` (`main`) | yylval.name = "main"; IDENT を返す |
| 8 | `() { return 42; }` | `"("` | '(' を返す |
| 9 | `) { return 42; }` | `")"` | ')' を返す |
| 10 | ` { return 42; }` | `[ \t\n]+` | 読み飛ばし |
| 11 | `{ return 42; }` | `"{"` | '{' を返す |
| 12 | ` return 42; }` | `[ \t\n]+` | 読み飛ばし |
| 13 | `return 42; }` | `"return"` | RETURN を返す |
| 19 | ` 42; }` | `[ \t\n]+` | 読み飛ばし |
| 20 | `42; }` | `[0-9]+` | yylval.int_val = 42; INT_LIT を返す |
| 22 | `; }` | `";"` | ';' を返す |
| 23 | ` }` | `[ \t\n]+` | 読み飛ばし |
| 24 | `}` | `"}"` | '}' を返す |
| 25 | （終端）| | 0 を返す（EOF）|

呼び出し元（次章の bison パーサ）に届くトークン列はこうなる。

```
INT, IDENT(main), '(', ')', '{', RETURN, INT_LIT(42), ';', '}'
```

文字の並びが、9個の意味あるかたまりに変換された。これが字句解析だ。


## 8. flex が生成するコード

`lexer.l` を flex に通すと、`lex.yy.c` という C ソースが生成される。

```bash
$ flex -o lex.yy.c lexer.l
```

中身は数百〜数千行の C コードだ（オートマトンを実装したテーブルとループが大半）。我々が直接読む必要はない。覚えておくべきポイントは2つだけ。

- **`int yylex(void)`** という関数が定義される。呼ぶたびに次のトークンを1つ返す。EOF に達したら 0 を返す。
- **`yyin`** というグローバル変数（`FILE *`）に入力ファイルを設定する。デフォルトは標準入力。

bison が生成するパーサは、内部で `yylex()` を呼んでトークンを取り出す。我々は `yyin` に入力ファイルを設定して、bison のパーサを呼ぶだけでよい。
